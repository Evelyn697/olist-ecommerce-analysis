# 巴西 Olist 电商平台BI分析

> 数据分析实战项目 | python + MySQL + Supserset | RFM用户分层 | 多维业务分析。 



## 一、项目概览

​	本项目基于巴西最大的电商平台之一 Olist 的Kaggle公开数据集，完成从数据清洗、维度建模、指标体系搭建和业务分析、Superset交互式BI看板搭建的完整数据分析流程，旨在为业务方提供经营大盘监控、用户群体分析、供应链管理与物流履约优化等提供数据驱动的异常监控和决策支持。



## 二、技术栈

| 环节 | 工具 |
|---|---|
| 数据存储 | MySQL 8.0 |
| 数据处理和分析 | Python（Pandas）、MySQL 8.0（多表JOIN、窗口函数、CTE） |
| BI与可视化 | Apache Superset（构建 Control Tower 监控看板） |
| 版本管理 | Git / GitHub |

## 五、分析模块与指标体系

​	指标口径定义见 [`docs/metric-dictionary.md`](docs/metric-dictionary.md)。

1. **经营总览**

   （1）核心KPI

   商品交易总额GMV、总订单数、客户数、平均客单价AOV、平均评分

   （2）时间趋势

   月度GMV、月度订单量、月度客单价

   （3）地区分布

   各州GMV

   （4）品类分布

   品类GMV Top10、品类订单量 Top10

2. **用户分析**

   （1）用户规模与增长

   复购率、用户月度净增长数、用户月度净增长率

   （2）RFM分层

   R+M二维分层，划分客户群体；各群体的客户数、GMV 贡献、平均客单价

   （3）用户-品类偏好

   不同客户群体（高价值 / 低价值）的品类购买偏好差异

   （4）用户-地域分布

   各州用户数、各州高价值用户占比

3. **物流履约与用户评价分析**

   （1）配送时效

   平均配送天数（承诺 VS 实际）、配送天数分布、各州配送时效比较、配送时效的月度趋势

   （2）物流延迟情况

   准时送达率；延迟率的月度趋势、地区差异、品类差异

   （3）订单评分分析

   评分分布、评分的时间趋势、各州评分比较

   （4）物流时效 & 评分分析

   不同配送天数的评分分布、评分与物流延迟情况分布热力图

## 七、核心业务发现

1. **供应链交付风险诊断**：整体准时足量交付率（OTIF）为 **91.9%**。延迟交付会导致客户满意度断崖式下跌：准时订单评分为 4.29 分，延迟 4-7 天的订单平均评分暴跌至 **2.11** 分（其中 58% 为 1 星差评），说明了交付时效对下游体验存在重大影响。
2. **物流时效与区域基建条件关联**：东南部（如 SP圣保罗州）物流时效极佳且评分高，而北部偏远州因基建薄弱，平均配送天数超 20 天，延迟率高。
3. **用户资产帕累托分布**：平台复购率仅 **3.01%**。高价值客户（Top 32%）贡献了约 60% 的 GMV，需要通过差异化服务防范高价值客户流失。



## 八、项目亮点

​	本项目展示了从数据准备到业务分析交付的完整流程，亮点如下：

- 在MySQL中构建 raw与 analytics 双层数据集架构，用事实表记录业务事件（如`fct_orders`（订单级交付事实）、`fct_order_items`（订单项事实）、`fct_delay_review`（延迟与评分聚合事实）），用维度表描述业务属性，如 `dim_customers`、`dim_product_category_translation`，展现数据底座与维度建模能力。

- 梳理并落地了业务指标字典，统一了GMV、OTIF等核心指标的口径，体现业务口径梳理和指标定义能力。

- 参考RFM模型，对平台用户进行了分层，并对各层用户的消费特征展开分析，体现用户运营分析能力。

  

## 九、业务策略总结

1. **交付风险预警机制**：
           根据分析，晚到 3天以上会引发评分断崖式下降。建议在 Control Tower 中建立动态预警：当订单状态判定为即将触发 3 天以上延迟时，系统自动触发预警，提前通知客服介入安抚或提供补偿，以拦截潜在的差评风险。

2. **承运商与区域物流策略分级**：
           针对北部及东北部偏远州，物流耗时长且不稳定。建议对承运商进行分区域绩效考核，并在前端下单时，针对偏远地区动态放宽承诺送达时间，以降低违约率。

3. **大件高延迟品类的供应链干预**：
           数据显示 `office_furniture`（办公家具）等大件商品的延迟率较高。建议将此类品类纳入重点监控对象，与对应的供应商和专线物流确认产能与发货节奏，避免因缺货或运力不足导致的超时。

4. **高价值客户的服务兜底**：
           针对贡献了 60% GMV 的高价值客户（Top 32%），一旦其订单发生物流异常，优先启用特快件补发或提供专属 VIP 客诉通道，最大化降低流失风险。

5. **优化客户留存策略：**

   ​        针对当前平台整体复购率较低（3.01%）的现状，建议优化用户留存和复购运营策略，例如老客优惠、复购提醒、会员权益等。

6. **中等价值客户升阶**：

   ​        可通过产品推送、优惠券发放等方式，向占比 36% 的中等价值客户交叉销售 `watches_gifts` 等高价品类，提升整体客单价。

   

## 十、复现步骤

```bash
# 1. 下载数据集，9 个 CSV 放入 data/raw
# 2. 配置数据库连接
cp .env.example .env    # 填入 MySQL 账号密码

# 3. 建库建表、导入数据
执行顺序：
sql/00_init/01_create_databases.sql			# 建库
sql/01_raw/02_create_raw_tables.sql			# 建表
scripts/etl/load_raw.py						# 导入数据
sql/01_raw/03_validate_raw_load.sql			# 验证导入正确性，或scripts\01_etl\validate_load.py
sql/01_raw/ 04_count_missing_values.sql		# 识别缺失值、异常值

# 4. 事实表与维度表构建
sql/02_analytics/							# 运行全部脚本

# 5. 业务指标构建与查询
sql/03_queries								# 分为3个模块：经营总览、用户画像、物流履约与用户体验
```
